# Engyne — Supabase + Render Deployment

## 1) Create Supabase project

1. Go to https://supabase.com/dashboard → **New project**
2. Note the database password you set
3. Open **Project Settings → Database**
4. Copy **Connection string** (URI)

Prefer **Transaction** pooler for Render (port `6543`) if offered:

```
postgresql://postgres.[PROJECT-REF]:[YOUR-PASSWORD]@aws-0-....pooler.supabase.com:6543/postgres
```

Or direct:

```
postgresql://postgres:[YOUR-PASSWORD]@db.[PROJECT-REF].supabase.co:5432/postgres
```

You can paste either form. Engyne auto-converts to `postgresql+psycopg://` and adds `sslmode=require` for Supabase hosts.

## 2) Local connect to Supabase (optional)

In `backend/.env`:

```env
APP_ENV=development
DEBUG=true
DATABASE_URL=postgresql://postgres.[REF]:[PASSWORD]@aws-0-....pooler.supabase.com:6543/postgres
SECRET_KEY=local-dev-secret-change-me
ADMIN_EMAIL=admin@engyne.example
ADMIN_PASSWORD=changeme123
CORS_ORIGINS=http://127.0.0.1:5173,http://localhost:5173
```

Then:

```bash
cd backend
.\.venv\Scripts\activate
pip install -r requirements.txt
python -m app.scripts.seed_admin
uvicorn app.main:app --reload --port 8000
```

Tables are created on startup (`create_all`). Seed creates admin + STARTER/PRO plans.

## 3) Deploy API on Render

### Option A — Blueprint (recommended)

1. Push this repo to GitHub/GitLab
2. Render Dashboard → **New → Blueprint**
3. Select the repo (uses root [`render.yaml`](../render.yaml))
4. Set these **secret / sync:false** env vars in the dashboard:

| Key | Value |
|-----|--------|
| `DATABASE_URL` | Supabase URI from step 1 |
| `ADMIN_PASSWORD` | strong password |
| `CORS_ORIGINS` | your admin URL(s), comma-separated |
| `ADMIN_REPORT_EMAIL` | your ops email |
| `RAZORPAY_*` | optional for now |

`SECRET_KEY` is auto-generated by Render.

5. Deploy → open `https://engyne-api.onrender.com/health` (name may vary)

### Option B — Manual Web Service

1. **New → Web Service** → connect repo
2. Root directory: `backend`
3. Runtime: **Docker** (Dockerfile in `backend/`)
4. Health check path: `/health`
5. Add the same env vars as above

## 4) Point Admin + Extension at Render

Admin (`martpilot-operations-hub/.env.production` or `.env.local`):

```env
VITE_ENGYNE_API_URL=https://YOUR-SERVICE.onrender.com
```

Extension: in DevTools / storage set `apiBase` to the Render URL, or change default in `extension/api/client.js` for production builds.

## 5) CORS

On Render set:

```
CORS_ORIGINS=https://your-admin-host,http://127.0.0.1:5173
```

Chrome extensions calling the API do not use browser CORS the same way for extension origins, but admin SPA does.

## 6) Verify

```bash
curl https://YOUR-SERVICE.onrender.com/health
curl -X POST https://YOUR-SERVICE.onrender.com/api/admin/auth/login \
  -H "Content-Type: application/json" \
  -d "{\"email\":\"admin@engyne.example\",\"password\":\"YOUR_ADMIN_PASSWORD\"}"
```

## Notes

- Free Render web services **spin down** after idle; first request can be slow (~30–60s).
- Do not commit real `DATABASE_URL` / passwords.
- Invoice PDFs write under `storage/invoices` (ephemeral on free dynos). Use object storage later for production PDFs.
- Redis is optional and not required for MVP.
